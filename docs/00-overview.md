# 双案例目标、输入与工程范围

本手册同时覆盖已有原生IPA的设备适配与原始游戏文件构建后的设备适配。src/、tools/、manifests/现有实现仍专属于丝之歌；新增卡比文档和用户截图不意味着宿主源码也已入库。

| 路线 | 输入 | 正确目标 | 入口 |
|---|---|---|---|
| 丝之歌A | SilksongNative-0.8.2原生Unity IPA与独立资源 | 取得真实窗口并同步surface/相机/HUD，补齐输入、五套布局与轻量界面 | [历史复盘](01-retrospective.md) |
| 卡比B | 原始Switch XCI/NSP与对应本地构建工具链 | 建立可游玩的iOS兼容宿主基线，再做Duo适配 | [卡比案例](cases/kirby.md) |
| 有完整工程 | 合法取得的引擎源码/资源 | 正式接入iOS和折叠窗口/输入/生命周期 | [下个游戏](08-porting-another-game.md) |

窗口铺满、ARM64指令集、成功签名、编译完成都不能单独证明游戏原生可玩或完整适配。两条现有路线都不是通用自动转换器。

## 共享产物与差异

共享：几何契约、归一化布局、可取消的输入与有限动画、真实监测、测试/回退/证据登记。差异：引擎ABI、动作/菜单映射、状态字段、图形呈现钩子、平台服务与资源链必须重新核实。

丝之歌通过scene桥接解决375×667旧窗口限制；卡比直接在自建iOS宿主中接入Duo。丝之歌没有重建游戏工程，卡比也不能被描述为拿到完整游戏源码重新编译。具体实现以两个案例事实为准。
