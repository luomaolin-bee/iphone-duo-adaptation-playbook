# 副屏设计与实现标准：让第二屏服务玩法

指南1.4 · 2026-11-03。本文是面向后续项目的实施规范和第三方代码阅读归纳，**不是丝之歌或卡比已完成副屏功能的报告**。原有五形态、原游戏比例、输入和外壳规则继续适用。

## 1. 先决定副屏的价值，再决定皮肤

每个项目先回答：玩家哪项高频任务被菜单打断？副屏能否减少操作或遮挡？数据从哪里来、可靠度如何？额外采样和绘制是否值得？没有可信数据或明确收益时，保留现有掌机控制区；不能为了填满第二屏伪造地图或状态。

| 级别 | 作用 | 进入条件 |
|---|---|---|
| S0 控制副屏 | 已验证虚拟键、可选低频倒影、主题外壳 | 默认保底；不新增游戏状态依赖 |
| S1 只读助手 | 小地图、装备、任务、技能说明等 | 目标游戏确有此内容；数据来源、版本和过期策略可核验 |
| S2 交互助手 | 原生菜单导航、点选或拖动物品 | S1已验证；动作有确认、拒绝和取消路径；先复用游戏原有动作 |
| S3 持久化工具 | 存档、物品或管理功能 | 独立立项；完整备份、恢复、并发与冲突验证；不默认随移植启用 |

这些级别是本手册新定义，非AnimalDuo原有接口。新项目先完成S0，再用一个最小S1页面证明收益。写入与云存档均非通用移植必需项。

丝之歌可研究地图/装备/任务只读页，卡比可研究能力说明、操作帮助或已验证的关卡信息。以上均为候选，不表示已有可信接口；不得根据截图捏造完整地图、库存或隐藏状态。

## 2. 几何：背景铺满，内容、触摸和铰链各有边界

沿用D01–D08，明确windowRect、gamePane、pictureRect、panelRect、contentRect、leftRail/rightRail、footerRect和局部坐标变换。背景/外壳可延伸到完整pane，重要文字与操作局部避让摄像头、圆角和系统手势。不能因为safe inset而裁掉整列游戏，也不能把整张副屏缩进小卡片只为给按键腾位。

副屏中心用于信息；两侧或可达区域放控制，底部可放分页。全套控件的可见轮廓、动画最大范围、摇杆最大行程及命中区均须计入适配，尺寸不足时切换紧凑布局/分页，不能只夹住中心点。绘制和命中必须消费同一个布局结果。

**不移植AnimalDuo的50/50比例为默认值。** 它的展开竖屏等分服务其动森助手；我们仍优先真实active水平铰链，无铰链按游戏与现有profile决定比例，卡比16:9嵌入上壳保留。横向无副屏可降级为游戏叠键和显式助手入口；外屏、内屏和左右分割另验，不以一张竖屏截图概括。

## 3. 数据链：游戏专用适配器 → 有版本快照 → 通用呈现

建议契约：

- 能力：game/build身份、schema、支持页面、read-only/允许动作；不匹配时禁用相关页面并给出原因。
- 快照：revision、采样时间（进程内单调时间）、scene/session、字段值、有效性与来源。UI读取完整不可变快照，不把游戏裸地址暴露给视图。
- 状态：loading / ready / stale / unsupported / error。数值未知不能写成0；失效后清除操作能力，过期内容明确标注或隐藏。
- 图像：资源key与版本、解码尺寸/像素数限制；异步任务归属页面和generation。切页、场景变化或后台后的旧结果不得覆盖新状态。
- 动作：action_id、目标实体/槽位token、expected_revision、状态前提、结果/拒绝原因；重试前重新读状态，默认不自动重试非幂等动作。

事件来源仍按真实游戏事件、已核实字段、HUD启发式、输入提示分级。**更快的快照不能把HUD猜测变成真实事件。** 文档中的时间字段、状态枚举、级别及模板为我们的建议契约，不是从AnimalDuo导入的可执行SDK。

## 4. 交互：页面变化不能吞掉游戏输入

切换地图/图鉴等信息页，不应无条件重建全部控制器或释放仍被合法按住的物理键。副屏手势、触屏虚拟键、实体手柄与助手导航分别持有输入状态，由单一入口合成游戏输入，防止一次点按重复脉冲。

取消的粒度必须明确：仅离开背包时取消背包拖动/事务；整机后台、控制区重建、方向/profile切换或触点失效则按现有规则释放所属虚拟输入。实体手柄按设备/玩家清理，不全局清零。相同profile内的信息切页不能误触发完整布局取消。

外接手柄隐藏虚拟键，**不等于隐藏有用的信息副屏**；信息面板、虚拟键、背景和设置入口使用独立可见性。隐藏整个副屏停止其采样；只隐藏按键仍可刷新正在显示的信息。Select/Menu完整验收继续执行1.3规则。未知模态保留可用的确认/返回入口，原生键盘/绘画只在已核实输入区域接收触摸。

## 5. 写入默认关闭，操作绑定最新状态

先只读。优先调用已验证游戏原生菜单/动作，避免旁路破坏任务、音效、动画与存档逻辑。游戏版本、对象/槽位身份或当前状态不匹配时拒绝操作，不能把拖动前的旧槽位套到新库存。

确需内存写入时须另做ADR：精确build与预期字节/值、类型、映射/写权限、范围/溢出/重叠检查；在已证明的同步事务窗口内验证整批前提，再一次提交，失败不能只写一半。不能把“先检查再异步写”当原子保证。只读失败退回unsupported/stale，不猜地址；不能跨游戏搬动森偏移或批写函数。

存档修改前保留完整可恢复备份，不只复制变化文件。云同步若另行启用，应以完整快照发布、冲突显式选择、验证临时产物后替换，避免最近时间戳直接覆盖；保留本机继续入口。此项来自第三方设计启发，不表示我们已完成云同步，也不表示iCloud跨设备已验收。

## 6. 性能：少做无效工作，不让副屏成为第二个游戏循环

1. 分清宿主状态采样、UI轮询、图像解码与最终呈现四层频率。AnimalDuo的Swift UI部分地图/背包/手机为0.2秒、其余0.5秒；宿主背包/手机50ms、地图200ms、其他500ms。**这些是动森案例值，非我们默认值，也不是端到端延迟。**
2. 页面不可见停止页面工作，后台清理或暂停；只在快照内容变化时发布UI。一个页面的可见性代次用于拒绝迟到的采样、图像和输入。
3. 预先展开不变模板；每帧仍重新求值动态绑定、可见性、重复次数、布局、绘制次序和命中。冻结整个frame会让库存和点击区域失真。
4. 当前可见图像工作集与可丢弃预热缓存分开，缓存被系统回收不能让当前页面永久空白。按字节与条目双重管理；NSCache限制是系统建议值，不能承诺进程硬上限。
5. 合并同key在途加载，失败缓存有TTL和数量上限，重试有退避、取消与代次；不能每帧重试缺失图片。内存压力优先丢弃预热内容，必要时降级可见图片并可恢复。
6. 用诊断确定热点再改图形资源索引/锁/着色器预热。索引修改要测试别名、重叠、删除搬移和地址复用；预热覆盖有限，未见场景仍可能编译。保留原版模拟速度，不以平滑显示宣称游戏FPS翻倍。
7. 分别报告冷启动、首开页面、切页、长时运行和后台恢复；纳入模板初始化/额外缓存代价。微基准加速不代表整机省电，Mac数据不等于iPhone热表现。

上述方法是优化候选。丝之歌、卡比尚未接入本章新副屏模块，现有busy-yield和真机功耗未测项继续保留。

## 7. 最小落地顺序与验收

P0给每页填[副屏方案模板](porting-standard/templates/SECONDARY_SCREEN.template.json)；P1保持原游戏可玩；P2在五形态中验证S0；P3接一页只读数据，验证身份不符、空值、场景切换和隐藏；P4证明收益后再开放单一动作；P5做同条件性能对照；P6真机验收后才升级状态。

验收必须包含：布局/命中一致、孔位和四角、翻页按住不丢、拖动取消、迟到结果、缓存被驱逐、短间隔状态变化、unsupported build、错误token/旧revision拒绝、内存压力、旋转/折叠、手柄重连、热降级及省电模式。增加副屏后原关卡、输入、存档均须回归。动作和写入未实现的项目标pending或not-applicable，不能靠演示图判通过。
