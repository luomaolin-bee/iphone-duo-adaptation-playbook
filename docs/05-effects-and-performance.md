# 视觉效果、反馈和性能口径

## GPU 倒影

早期系统截图/CPU读大图不适合持续捕获 Metal 游戏画面。最终方法识别本构建的 Unity 呈现 block，在提交前追加 GPU 工作：

1. 取对应的 `CAMetalDrawable.texture`，核对 layer、pixel format、sample count 和 framebufferOnly。
2. MPS bilinear 缩小到最长边256px。
3. MPS Gaussian blur，sigma6。
4. 写到复用的小 shared buffer。
5. 完成回调创建小 UIImage，在主线程更新 UIImageView，垂直翻转形成倒影。

只允许一帧在途，复用两张纹理与一个 buffer；不保存历史帧，不落盘。背景、渐变和蚀刻分层，倒影刷新不重画装饰。

当前档位：关闭；均衡目标20FPS；流畅目标30FPS。低电量目标12FPS、较严重热状态10FPS；后台和编辑时暂停捕获。这些是倒影目标，不是游戏限帧，也不是每个游戏渲染帧都复制一份。

最长边256对应 RGBA 像素本体最多约256KiB；实际 readback 有行对齐，MPS/驱动/图层还有额外分配，不能拿这个数当整个适配层或整个游戏 RAM。

## 液态玻璃和可见性

SDK/系统可用时使用 `UIGlassEffect`，否则材料降级；尊重降低透明度。透明的 face 覆盖在原命中区域上，不截获游戏触摸。

初次图标不出现的问题来自首次重绘/前景 glyph。修正为创建和标签/尺寸变化时主动重绘，返回/更多用明确的前景 UIImageView。玻璃效果不是按一下才初始化。

## 场景、生命值和交互

只读 `GameManager`、`UIManager`、`PlayerData`、`HeroController` 的已核实字段，缓存字段元数据，不长期持有裸托管对象。约200ms采样：

- 场景、UI状态、背包页、接管输入状态变化 → 短水波/淡入。
- 普通生命+蓝血下降 → 红色边缘呼吸；增加 → 青绿色提示。
- 货币变化 → 较轻暖色提示。
- 菜单快捷键/菜单确认按压 → 装饰过渡。

加载、暂停、场景刚变化、后台返回、异常读数和冷却期会抑制伤害提示。生命采样无法区分200ms以内又受伤又回血的全部事件；未证明覆盖每一种商店。

红边使用四条窄渐变，不生成整屏红图。水波只有三个64×64缓存 shape；粒子最多18个小层，动画有限时长，完成移除。遵循减弱动态效果，可从更多单独关闭场景反馈。

## Fake Lu 皮肤

解码本地已有资源包，定位到 `1 - Team Cherry Logo` 和 `TeamCherryLogo`。针对确切对象把视觉 scale 置零，不停用场景控制器，不删除加载步骤，也不改游戏标题本身。

用户参考图在启动时解码为最长边720px缩略图，加入淡入、录入式字幕、青紫故障条、横向抖动和眼部明暗；动画结束释放大图。标题界面使用小型文字标签。

这是本地界面皮肤，不是原游戏作者身份的改变。其他资源包若名称不同，要先查对象再改，不能宽泛地隐藏所有含“Logo”的物体。

## 监测项定义

| 项 | 实际含义 |
| --- | --- |
| FPS | 优先 Metal drawable presented callback 计数；无数据时明确“提交FPS” |
| Frame ms | 采样区间平均帧间隔，不是某个CPU线程耗时 |
| CPU % | 本游戏进程累计 CPU 时间差；单核心满载100%，可超过100% |
| GPU ms | 每四个呈现命令抽样一次的完成GPU时间差，包含追加倒影工作；不是整机GPU利用率 |
| Render | Metal drawable 实际像素尺寸 |
| MEM | 当前进程 physical footprint；报告另存 resident MB |
| 热状态 | 系统 nominal/fair/serious/critical 对应正常/温热/较热/过热；不是摄氏温度 |
| 倒影 FPS / ms | 成功交付倒影的频率与端到端延迟 |

CPU/内存约1Hz，监测关闭时不持续查询；GPU时间也只在监测/编辑开启时抽样。初次开启需要等采样。

## 实测与下一步优化

收尾图中整个应用约2GB，不能宣称是低内存游戏或适配层只占某个固定数值。要做进一步归因，应在同一场景和同一存档比较：原基线、倒影关闭/均衡/流畅、玻璃开/关、反馈开/关，记录持续时间、温升、footprint和帧时间分布。

当前截图不是内存增长曲线。横向图里倒影0/4FPS可能是关闭、切换后残留或采样窗口影响，不能据此认定横向也在持续倒影。
