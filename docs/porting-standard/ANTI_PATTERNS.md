# 错误做法与纠正依据

| 错误 | 实际后果/依据 | 下次正确动作 | 规则 |
|---|---|---|---|
| 把已有IPA适配称为完成原平台移植 | 丝之歌缺完整Unity工程，起点已在iOS运行 | 先写路线A/B及目标边界 | §1 |
| 仅改plist或SDK标记就认定窗口适配完成 | 丝之歌窗口bounds仍旧，标记改动不是SDK重建 | 校验scene、真实bounds及渲染链 | D01/D02 |
| 只拉UIView以填满屏幕 | 人物与HUD变形、竖屏扁小 | 同步surface/viewport/方向和pictureRect | D02/D03 |
| 为孔位空出整列/禁止拖动整列 | 两项目右侧空区和编辑限制 | 画面完整pane，关键UI局部避让 | D04 |
| 所有角统一圆角/描边反馈各自画 | 外屏竖屏右下角露出、反馈膜越界 | 共用路径，局部角参数与真机照片验证 | D06 |
| 上下外壳各画一个矩形、不处理连接 | 黑缝与生硬拼接 | 用真实铰链划区，软件连接处自然过渡 | D05/D06 |
| 根面板覆盖键位或反馈模型层默认有颜色 | 键盘不见、黄色膜待机残留 | 层级分离、外壳内裁切、模型透明、结束移除 | D07/E03 |
| 复制旧Unity GCHandle/裸指针假设 | 丝之歌托管raycast与菜单gate路径撤回 | 依身份和ABI重新验证，不长期裸持对象 | B01 |
| 在Mach-O头部填充区放可执行助手 | 上一项目state列为撤回路径 | 遵循现有段保护和可执行代码布局，单独验证 | B01 |
| 看到设备RAM够就否认Jetsam | 卡比约3376MiB进程预算，有系统杀进程证据 | 分析Jetsam、footprint和实际写页 | F02 |
| 盲缩内存池、全局加sleep | 卡比加载卡住；其他标题曾加载慢/降帧 | 按调用方与指令证明根因后改 | F02 |
| 每次布局清空识别基线、过长冷却 | 血条反馈延迟/缺失，连续事件被抑制 | 稳定状态保留基线，测试短间隔事件 | E02 |
| 把B键提示称为真实攻击/蓄力，把截图识别称为可靠生命事件 | 卡比目前只有启发式与输入边沿 | 来源/置信/限制清楚命名 | E01 |
| 为低延迟无限提高捕获率或常驻模糊粒子 | 额外负载，未做功耗对比不能承诺省电 | 小图共享、单帧在途、分别节流、热降级 | F03/E03 |
| 静态截图60FPS当全关卡与热稳定验收 | 两项目长期/全菜单验证不足 | 同条件连续测试，标明样本时长 | F04 |
| 任意删着色器、复用错误chain、UI构建误触发大规模重新转换 | 后续关卡风险、资源身份改变 | 全路径保留与精确校验；改输入才重建 | B02/B03 |
| 目录名或源码版本代替实机验证版本 | duo-0221目录实际state为0.2.20、用户验证0.2.19 | 三类身份分别记录 | §1/§6 |
