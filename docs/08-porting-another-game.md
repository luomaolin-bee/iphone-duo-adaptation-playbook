# 迁移到下一款游戏：双路线执行方案

先确定输入，再按[执行标准](porting-standard/STANDARD.md)和[验收关卡](porting-standard/ACCEPTANCE.md)推进。原丝之歌已有IPA路线与卡比原始文件路线必须分开。

| 输入 | 首先完成 | 后续设备适配 |
|---|---|---|
| 完整工程 | 引擎/平台正式构建与生命周期 | 原生接入窗口、相机、HUD、动作系统 |
| 已可运行iOS IPA | 身份匹配、引擎/渲染/输入调查、可回退包 | 有限桥接实验，参考丝之歌，重新核实ABI |
| 原始其他平台游戏文件 | 提取/调查、平台服务与图形兼容、正确的iOS运行基底 | 参考卡比bring-up阶段，再复用Duo机制 |
| 只有截图/视频 | 视觉或交互原型 | 无法据此生成真实游戏 |

## 实施顺序

1. 保存输入清单、hash、引擎/模块build、目标和回退点。
2. 先证明可启动、可加载、可玩，再调整窗口、比例和输入。
3. 采集真实window/hinge/safeArea与drawable像素，建立五profile与共享裁切。
4. 保留原动作，验证多指、滑动、松手、取消、手柄和编辑持久化。
5. 从目标游戏提取视觉令牌，选择可信事件源，定义效果寿命/预算/取消；不得将按键提示当真实状态。
6. 同条件对照倒影、玻璃与反馈开关；定位CPU/GPU、内存与包体各自原因，不盲调百分比。
7. 构建身份/资源链/CRC/hash检查，输出未签名包、记录和已知未验项目。

## 复用边界

可复用坐标与布局模型、可取消输入、限频小图、有限动画、监测口径及证据流程。必须重新绑定引擎接口、菜单和战斗动作、状态字段、资源链与模块补丁。丝之歌与卡比的视觉都只作案例，不是统一皮肤。更多反例见[ANTI_PATTERNS](porting-standard/ANTI_PATTERNS.md)。
