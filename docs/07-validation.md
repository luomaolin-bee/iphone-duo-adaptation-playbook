## 已支持的结论

- 游戏可以进入实际游玩场景，横向与上下分区效果可见。
- 按键已呈现玻璃风格和自定义布局；监测可以放在上方游戏区。
- 图中瞬时性能和倒影读数落在表列范围。
- 更早0.2.16、0.2.17、0.2.18获得用户的明确逐轮反馈，见复盘。

## 仍未证明

- 每种模式精确 window/hinge/safeArea 数值；需要诊断JSON。
- 每个商店、背包页、返回路径都正确。
- 水波、受伤/回血、品牌动画的完整时间行为；静态图不能验证。
- 长时间内存是否增长、最差帧时间、持续温升、耗电。
- 锁屏/切后台/系统杀进程后的恢复；没有证明任意时刻存档保全。
- 其他游戏、其他引擎版本或其他资源包的兼容性。

## 本机检查

原发布流程保留的检查包括：

- 0.2.16：126项 ARM64 分区/方向组合、32项实际菜单指令组合。
- 0.2.17：75项控制区碰撞检查、1000次HUD偏移/恢复迭代；GPU host测试因无设备未实际编码。
- 0.2.18/0.2.19：70项边缘拖动、五 profile独立保存、排列和菜单策略；14个默认可编辑元素不重叠。
- 0.2.19：65个非监测默认矩形保持与0.2.18一致；1108项反馈策略与非法生命值保护；Darwin自身CPU时钟和内存接口可读。
- 严格iOS编译、静态分析零诊断、ZIP完整性和精确改动范围。

这些是不同层次的检查，不可以合并宣传为“所有设备测试全部通过”。本次仓库重构的工具另有 `evidence/repository-validation.json`。

## 推荐后续真机矩阵

每次版本只验证与改动相关的场景：冷启动 → 五形态切换 → 布局保存 → 攻击确认/返回 → 背包/商店 → 受伤/回血 → 返回游戏 → 后台/锁屏 → 继续运行。

有异常先导出匹配版本诊断；崩溃核对 `.ips` binary images的UUID。长测需记录同一存档、场景、设置、时长和设备状态，不能只贴一张“60FPS”。
